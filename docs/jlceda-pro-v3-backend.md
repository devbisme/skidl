# 嘉立创 Pro V3 后端开发记录

## 目标

在 `src/skidl/tools/jlceda_pro/` 中实现独立的嘉立创 Pro V3 后端：

```text
ENET 2.0
  -> SKIDL Circuit
  -> 本地嘉立创符号资源
  -> 公共布局和布线
  -> 嘉立创 Pro V3 原理图文件
```

KiCad 后端保持不变。正式导出的目标是可导入、可编辑的 `.esch` 原理图文件，
不要求生成完整 `.eprj` 工程。正式导出不得依赖 GUI、在线服务或未公开接口。

## 实现原则

- `examples/jlc/Netlist_for_case1.enet` 只用于端到端验收，不作为格式定义。
- 禁止写死 case1 的器件哈希、位号、网络名、符号图形或目录布局。
- 符号和器件必须按本地资源中的真实哈希匹配；缺失时明确报错。
- 在样本未确认前，不根据 `DeviceName` 猜测符号，也不假设 `.elib` 的内部目录结构。
- 读取未知图元时保留原始字段，避免往返写出时丢失扩展数据。

## 已完成

- V3 日志行 `outer-json||inner-json` 的解析和稳定写出。
- 按 `type + id + ticket` 归并日志；同 ticket 时按 `client` 决胜。
- 删除记录的保留和过滤。
- mil 与嘉立创 `0.01 inch` 单位换算。
- 稳定 UUID、紧凑图元编号和递增 ticket。
- 通用资源 reader：支持解压目录、zip 形式资源包和单资源文件。
- SKIDL 工具自动发现需要的 `jlceda_pro` 后端骨架。

## 待实现

### 样本到位后优先实现

- 确认 `.elib`、`.esch` 和解压目录中的真实文件布局。
- 将 `Symbol`、`Device`、`Footprint` 哈希映射到对应资源。
- 解析 `.esym` 中的 `PIN`、`ATTR`、矩形、圆、圆弧、折线和文本。
- 将符号引脚转换为 SKIDL `Pin`，并保留方向、长度、相对坐标和 `partId`。
- 根据符号图元计算边界框，覆盖旋转和镜像。

### 符号加载通过后实现

- 接入公共 `SchNode`、`place()` 和 `route()`。
- 输出 `SCH_PAGE` 中的 `COMPONENT`、`ATTR`、`WIRE` 和网络属性。
- 将连续路由线段合并为 `WIRE.dots`。
- 输出网络标签、电源标识和必要结点。
- 写出可由嘉立创 Pro V3 导入并继续编辑的 `.esch` 原理图文件。

### 闭环验证

- 使用 case1 生成 `.esch` 并在嘉立创 Pro 中导入。
- 检查器件、连线、标签可编辑。
- 重新导出 ENET，对比位号和引脚网络关系。
- 在联动仓库增加 CLI、文档和端到端测试。

## 需要准备的本地样本

### 最小开发包

提供一个可离线解压的 `.elib` 或资源目录，至少包含：

- 一个普通两引脚电阻。
- `HDR-M_2.54_1x20P`。
- `STM32F103C8T6`。
- 每个器件对应的 Symbol、Device 和 Footprint 资源正文。
- 一份说明文件，列出资源哈希与器件名称的对应关系。

### 最小原理图样本

从嘉立创 Pro V3 导出以下 `.esch` 原理图：

- 单个电阻。
- 两个电阻和一根导线。
- T 形结点。
- 一个网络标签。
- 一个电源标识。

每个原理图同时保留重新导出的 `.enet`，并附一行说明界面中实际绘制的内容。

### 后续覆盖样本

- MCU 与连接器。
- 多单元器件。
- 自定义符号。
- 旋转和镜像后的器件。
